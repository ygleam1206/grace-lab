# 任务：为 Grace Lab 博客实现支持富格式粘贴的文章编辑器


## 核心需求

我要实现类似 macOS 备忘录的富文本粘贴体验。

当我从 Mac 备忘录、网页、Word 或其他支持富文本的软件中复制内容，并粘贴到博客文章编辑器时，应尽可能保留原始格式。

重点支持：

1. 字体大小和标题层级。
2. 粗体、斜体、删除线、下划线。
3. 文字颜色及合理的背景颜色。
4. 段落、换行、引用块。
5. 有序列表、无序列表及缩进。
6. 超链接。
7. 图片（如果现有上传和存储机制支持，请优先复用）。
8. 代码块及基础代码格式。

同时支持直接输入、编辑和修改已有文章，而不仅仅是粘贴。

## 三、技术实现要求

### 1. 先分析现有项目

开始修改前，请先检查：

- 现有文章编辑页面和编辑器组件。
- 文章的数据结构、存储格式及读取流程。
- 保存、发布、更新文章的 API。
- 文章详情页的 Markdown/HTML 渲染方式。
- 现有依赖中是否已有富文本编辑器。
- 本地编辑端与 GitHub Pages 静态公开端之间的数据生成流程。

先给出简短的现状分析、实现方案和可能的兼容性风险，再开始编码。

### 2. 选择合适的富文本编辑器

优先评估 TipTap（基于 ProseMirror）是否适合当前项目。

如果已有编辑器可以扩展，应优先复用；如果需要引入新依赖，先检查 Next.js、React 和 TypeScript 的版本兼容性。

编辑器需要支持粘贴 HTML 格式，而不是只读取剪贴板中的纯文本。

如果编辑器组件依赖浏览器 API，请正确处理 Next.js 客户端组件和服务端渲染的边界。

### 3. 正确保存富文本

不能只在编辑器中显示格式，却在保存后丢失格式。

请设计与现有项目兼容的持久化方案，例如经过清理的 HTML 或编辑器 JSON 文档。

具体选择应基于现有文章结构和渲染流程。保存后重新打开文章，格式必须能够恢复。

如果需要修改数据库结构或文章数据格式，请先说明迁移方案，兼容已有文章，不能直接覆盖或清空旧数据。

### 4. 适配文章展示页面

确保发布后的文章页面能够正确显示富文本格式。

需要特别检查：

- 标题、字号、颜色和段落间距。
- 列表、引用、链接及代码块。
- 图片地址和静态资源路径。
- 现有 Markdown 文章的兼容性。
- GitHub Pages 静态导出后的显示效果。

如果采用 HTML 存储，必须在保存或渲染环节进行合理的 HTML 清理和安全过滤，防止脚本、事件处理器及危险 URL 注入。

不要直接执行或信任用户粘贴的 HTML。

### 5. 保持现有架构

- 保留现有文章管理、保存、发布和编辑功能。
- 保留原有数据库、文件及上传目录中的数据。
- 不要将本地编辑后台或写入 API 暴露到公开网站。
- 不要为了实现富文本而重写整个博客。
- 不要随意修改与本需求无关的功能。
- 继续遵守现有 GitHub Pages 的静态部署配置。

## 四、测试要求

实现后请实际验证以下场景，而不是只检查代码能否编译：

1. 粘贴一段包含标题、粗体、不同字号、颜色、列表和链接的富文本。
2. 保存文章并重新打开，检查格式是否保留。
3. 发布后检查公开文章页面的排版。
4. 检查已有 Markdown 文章能否正常显示。
5. 测试从 Mac 备忘录复制内容的效果；如果当前环境无法直接执行该操作，请明确说明，不要声称已经验证。
6. 测试纯文本粘贴和普通键盘输入。
7. 检查恶意 HTML 是否会被过滤。
8. 检查静态导出和 GitHub Pages 的资源路径。
9. 检查原有文章、图片和管理功能是否受到影响。

请运行项目现有的 lint、类型检查、构建或其他适用测试，并报告实际结果。
