# 需求：将博客笔记分类改造为文件夹式展示

请先阅读当前博客项目的代码，了解现有技术栈、笔记模块、分类数据结构、接口和页面路由，再在现有项目基础上完成改造。

## 一、核心需求

将笔记模块从当前的分类导航与笔记列表展示，改造成**文件夹卡片式浏览界面**。

1. **笔记首页展示分类文件夹**
   - 默认展示所有笔记分类，不直接展示分类下的全部笔记。
   - 每个分类以独立的文件夹卡片呈现。
   - 卡片包含封面图片、分类标题、该分类下的笔记数量。
   - 封面图片与标题排版美观，整体具有现代个人知识库的视觉效果。
   - 采用响应式网格布局，适配电脑与移动端。

2. **点击文件夹进入分类详情**
   - 点击分类卡片后，进入对应分类的详情页面。
   - 详情页展示该分类下的所有笔记。
   - 保留现有笔记列表的必要功能，包括查看笔记、搜索或已有的筛选功能。
   - 提供清晰的返回入口或面包屑导航，方便返回文件夹首页。

3. **文件夹封面管理**
   - 每个分类支持设置封面图片。
   - 优先复用项目现有的分类管理功能和图片上传机制。
   - 如果目前没有封面字段或编辑入口，再根据现有技术栈设计最小化的扩展方案。
   - 未设置封面时，使用统一的默认封面，避免出现图片缺失或布局错乱。

## 二、视觉设计要求

- 采用简洁、现代、有设计感的个人知识库风格。
- 文件夹卡片以封面图为视觉主体，标题清晰醒目。
- 卡片圆角适中，间距合理，悬停时提供轻微的交互反馈。
- 图片使用统一比例，并进行适当裁切，避免卡片高度不一致。
- 页面应有良好的留白、字体层级和视觉一致性。
- 不要做成传统后台管理系统的密集表格，也不要过度使用渐变、阴影和动画。

## 三、技术实现约束

1. 必须基于当前项目的实际技术栈和代码结构实现，不得擅自重建项目。
2. 优先复用现有分类、笔记、接口、组件和路由。
3. 先检查数据库结构。如果现有分类表可以直接扩展，则只增加必要字段，例如 `cover_image`，具体命名遵循项目规范。
4. 如果需要修改数据库，提供明确的 SQL 迁移脚本，不得直接删除或重建原有表。
5. 保证原有笔记数据、分类关联关系及笔记详情页面正常工作。
6. 如果需要新增或修改后端接口，保持现有接口风格，并处理空数据、无效分类 ID、图片缺失等情况。
7. 不引入不必要的新依赖，不进行与本需求无关的大规模重构。

## 四、实施步骤

1. 检查项目结构，定位笔记页面、分类管理、数据模型、后端接口和路由。
2. 简要说明当前实现方式及改造方案。
3. 实现分类文件夹卡片首页。
4. 实现点击文件夹进入分类笔记列表的交互与路由。
5. 实现分类封面图片的读取、展示及必要的设置功能。
6. 运行项目并验证页面、接口、数据兼容性及原有功能。

## 五、验收标准

- 进入笔记模块后，首先看到分类文件夹，而不是所有笔记。
- 每个文件夹都能显示标题、封面和笔记数量。
- 点击文件夹后，只展示该分类下的笔记。
- 可以从分类详情返回文件夹首页。
- 原有笔记及分类数据不会丢失。
- 未设置封面时页面仍然正常。
- 现有笔记详情、搜索及其他原有功能不受影响。
