# Grace Lab 公网静态博客改造任务

请基于当前仓库实现“本地管理端 + GitHub Pages 公网只读站点”的双模式架构。

## 目标

1. 保留现有 Next.js + SQLite 本地博客管理功能，不破坏现有笔记 CRUD、分类、文件管理和学习记录功能。
2. 新增独立的公开静态站点，部署到 GitHub Pages，供访客免费阅读笔记。
3. 不部署现有管理 API，不把 SQLite 数据库、私密笔记和管理凭证发布到公网。
4. 不要求在线编辑、在线上传；笔记更新后，通过本地命令重新生成并发布静态站点。

## 实现要求

1. 先检查项目目录、数据库表结构、笔记公开状态字段、笔记详情页面、图片引用方式和现有构建配置，再制定改造方案。
2. 新建独立目录 `public-site/`，作为公开站点，使用兼容 GitHub Pages 的 Next.js 静态导出配置，输出到 `out/`。
3. 新建数据导出脚本，从现有 SQLite 数据库读取笔记、分类及必要的标签，生成公开站点需要的 JSON 数据。
4. 默认采用白名单机制：只有明确标记为公开的笔记才能导出。如果现有数据库没有公开状态字段，先分析当前笔记数据和现有产品逻辑，设计安全的公开标记机制；不能默认把所有笔记公开。
5. 图片只复制公开笔记实际引用的图片。禁止复制数据库文件、管理配置、私密附件和无关上传文件。
6. 公开站点至少包含首页、笔记列表、分类浏览和笔记详情；支持刷新页面后正常访问，适配 GitHub Pages 的仓库路径前缀。
7. 提供本地发布命令：先导出公开数据，再构建静态站点。具体命令写入 `package.json`，并在 README 中说明。
8. 新增 GitHub Actions 工作流，将生成的静态文件部署到 GitHub Pages。不要把数据库或原始 `uploads/` 目录上传为构建产物。
9. 检查 `.gitignore`，保护本地数据库、私密笔记数据、环境变量和管理凭证。
10. 保留现有本地运行方式，不擅自删除、迁移或清空数据库与上传文件。

## 验收标准

- 原有本地博客可以正常启动，CRUD 功能没有回归。
- 只有明确公开的笔记会出现在静态站点中。
- 公开笔记引用的图片可以正常访问。
- 静态站点不包含管理 API、数据库文件、私密笔记和凭证。
- 静态导出及构建成功，GitHub Actions 能部署。
- 提供具体运行命令、GitHub Pages 设置步骤和验证清单。

先检查代码并给出改造计划，再实施修改。完成后汇报实际修改的文件、执行过的测试、未解决的问题。不要仅凭代码编译成功就宣称部署验收通过。
